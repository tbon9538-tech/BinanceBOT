## 2. 阶段明细

### A 运行保障（P0，最先做）

| 任务 | 负责 | 输入 | 退出条件 |
|---|---|---|---|
| A1 Telegram 通知 | 用户提供 token 与 chat_id → 开发配置 | `.env`：`TELEGRAM_BOT_TOKEN`、`TELEGRAM_CHAT_ID` | 手动触发一次日报与一次 WARN 告警，手机都能收到 |

| A3 状态库自动备份 | 开发 | 每次运行成功后，用 SQLite backup API 复制 `data/state-<env>.db` 到 `data/backup/`，保留 30 份 | 单元测试覆盖；从备份恢复后 `status` 结果一致 |
| A4 代码异地备份 | 用户决定 → 开发 | 私有远端仓库（例如 GitHub private） | `git push` 成功；`.env`、`data/` 不在仓库中 |
| A5 轮换密钥 | 用户 | testnet 与 demo 后台 | 两套 Key 都重新生成，`.env` 已更新，容器重启后 `status` 正常 |

### B demo 前向观察（进行中，≥ 4 周）

- **运行**：本机 Docker 常驻，每天 00:10 UTC；电脑与 Docker Desktop 需保持开机。
- **每周**：`docker compose exec bot uv run --no-sync python -m bot forward`，结果追加到 `doc/demo_log.md` 的周表。
- **C4 的进入条件**（dev_plan M7-3，最早约 2026-11-30）：

| 指标 | 合格线 |
|---|---|
| 连续运行 | ≥ 28 天 |
| 漏跑 | ≤ 2 天，并且每一次都有原因 |
| 对账 | 没有 WARN 级以上的 `RECONCILE_DIFF` |
| 异常 | 没有未处理的 `UNHANDLED_EXCEPTION` |
| 成本 | 实际手续费率和成交偏移，与回测假设（0.1% + 0.05%）的偏差在 ±50% 以内 |
| 一致性 | 与研究引擎同期模拟的日收益相关系数 ≥ 0.9 |

- **注意**：4 周的收益在统计上没有意义。C4 主要检验**系统运行是否可靠**，不检验策略好坏；策略层面的结论仍然是"保留集未通过"。

### R 研究线（持续，与以上并行）

**规则**：每一项都**先在 `doc/research/log.md` 预注册**，只用研究集（≤ 2025-06-30）开发，试验计入 `trials.csv`；保留集**不再使用**。

**样本外检验方式**：执行回放已证明研究引擎与实盘流程的差异 ≤ 0.4%，所以新方案**不需要单独的 demo 账户**，直接用研究引擎在前向数据（2026-11 之后、由容器每天积累的行情）上模拟即可。

**替换门槛（建议，用户可调整）**：前向数据至少 6 个月；新方案在前向期的夏普和 Calmar 都不低于当前配置，并且满足预注册的研究集标准。

| 编号 | 方向 | 理由 / 文献 | 实现成本 |
|---|---|---|---|
| R3 | CTREND 式综合信号（多周期价格 + 成交量） | Fieberg et al. 2025（JFQA），扣除成本后在大币中依然有效 | 中 |
| R4 | 核心袖子扩展为 BTC + ETH（各自做趋势过滤） | 分散单一资产风险 | 低 |
| R5 | EWMA 波动率估计 | E4b 推迟项 | 低 |
