## Q0【阻塞：C0】第一版的策略结构 ✅ 已决定

探索性回测（`strategy_review.md` §5）的结果：

| 方案 | 2020-01～2022-09 夏普 | 2022-10～2025-06 夏普 |
|---|---|---|
| v2 的纯山寨动量轮动 | 1.8 | 0.5 |
| 同一大盘过滤下只持有 BTC 的趋势策略 | 1.4 | 1.4 |
| 两者各占一半 | 1.9 | 1.0 |

两者各占一半时，全样本最大回撤约 −25%（样本内，偏乐观）。

| 选项 | 内容 |
|---|---|
| A（推荐） | **核心–卫星**：BTC 趋势核心与山寨动量卫星各占 50%，权重由实验 E7 在 {0.3, 0.5, 0.7} 中确认。如果卫星在样本外没有增益，就退化为纯 BTC 趋势。 |
| B | 保持 v2 的纯山寨动量轮动，只修正漏洞和参数。 |
| C | 只做 BTC 趋势（加波动率目标）。最简单，但只押注单一资产。 |

**推荐 A**。理由来自分散化，而不是样本内寻优。两个袖子共用同一套代码（只是参数不同），额外的开发量很小；同时，这也是第二阶段多策略架构需要的结构。

**✅ 决定（2026-11-01）：采用 A。**

## Q1【阻塞：C0】收益与风险目标是否调整 ✅ 已决定

初步验证和蒙特卡洛估算（`strategy_review.md` 第 5、6 节）表明，"年化 30%～60%、最大回撤 ≤ 30%、Sharpe > 1、Calmar > 1"这一组目标，在只做多、不加杠杆的现货约束下**不能同时稳定达成**。按样本外较现实的夏普（约 1.0）估算，要拿到 30% 以上的年化收益，组合波动需要在 35%～40%；而波动在 40% 时，5 年内最大回撤超过 30% 的概率约为 95%。

| 选项 | 内容 |
|---|---|
| A | 保留原目标。研究阶段以原目标作为通过线，大概率所有方案都不通过。 |
| B（推荐） | **以风险为硬约束，收益为期望**：完整周期最大回撤 ≤ 35%（目标 30%），Sharpe ≥ 0.8，Calmar ≥ 0.6，熊市年份亏损 ≤ BTC 同期亏损的 1/3；年化收益期望 15%～35%（牛市年份可以更高，震荡年份可能为负）。 |
| C | 以收益为硬约束：年化 ≥ 30%，接受 45%～55% 的最大回撤。 |

**推荐 B**。对小资金来说，先证明风险控制有效，再考虑提高风险预算。B 对应 v3 的默认目标波动 0.30（待研究）。

**✅ 决定（2026-11-01）：采用 B。** 研究阶段的通过线以 spec v3 §1.1 的硬约束为准。

## Q4【阻塞：C0】交易所客户端：自研轻量客户端，还是官方 `binance-sdk-spot` ✅ 已决定

`binance-connector` 已经标注 deprecated。官方替代品 `binance-sdk-spot` 要求 Python ≥ 3.11，版本迭代很快（2026-10 已到 13.x）。

| 选项 | 内容 |
|---|---|
| A（推荐） | **自研轻量 REST 客户端**，基于 `httpx` 或 `requests`，只实现约 10 个接口，签名支持 HMAC 和 Ed25519。超时、未知状态、限频响应头都能精确控制，测试时也容易 mock。 |
| B | 使用 `binance-sdk-spot`。少写一些签名代码，但要跟随 SDK 的版本变化，而且它对超时和 5xx 的处理细节需要逐一核实。 |

**推荐 A**。签名代码大约 50 行，有官方示例可以对照，成本很低。

**✅ 决定（2026-11-01）：采用 A。**

## Q5 Telegram 命令的范围 ✅ 已决定（选 C，未采用推荐）

| 选项 | 内容 |
|---|---|
| A（推荐） | v1 只做**通知**（日报、告警），外加一个 `/kill` 命令。本地 kill 用命令行和 `KILL` 文件。 |
| B | 按 v2 实现 `/status`、`/pause`、`/resume`、`/kill` 全部命令。 |
| C | v1 只做通知，不接收任何命令。 |

**推荐 A**。远程紧急停止是真正的刚需；其他命令依赖常驻轮询进程，可以放到 v1.1。

**✅ 决定（2026-11-01）：采用 C**，v1 的 Telegram 只发通知，不接收任何命令。理由：v1 没有常驻进程，`/kill` 只能在下一次每日运行时才被读到，无法及时响应，反而会给人"已经停了"的错觉。紧急停止方式：SSH 登录服务器执行 `python -m bot kill`，或在项目根目录创建 `KILL` 文件。spec §5.5、§10.1、§12 已同步修改。

| 选项 | 内容 |
|---|---|
| A（推荐） | v1 留在现货账户，不做理财。 |

## Q9【阻塞：C0】新币审核流程 ✅ 已决定

2026-06 起币安上线了约 100 个代币化股票/ETF 交易对（例如 `NVDABUSDT`、`TQQQBUSDT`），而 API 里没有区分资产类别的字段。

| 选项 | 内容 |
|---|---|
| A（推荐） | **规则排除 + 人工审核**：新出现在候选池里的资产默认不交易，系统发告警；人工把它加入 `approved_assets` 或 `excluded_assets` 之后才生效。回测时用"历史上所有非排除类资产"近似。 |
| B | 只靠规则自动排除（名称模式、稳定币检测）。会漏掉新的资产类别。 |

**推荐 A**。因为有 90 天的上市期限制，人工审核有充足的时间窗口，每周看一次告警即可。

**✅ 决定（2026-11-01）：采用 A。**

## Q11 第一版是否保留 ATR 追踪止损 ✅ 已决定

初步数据显示，止损对收益和回撤的贡献**都是负的**（`strategy_review.md` §5.3、§5.4）：

| 配置 | 夏普（无止损 → 有止损） | 最大回撤（无止损 → 有止损） |
|---|---|---|
| v2 默认配置 | 1.20 → 1.14 | −39% → −44% |
| 推荐的卫星配置 | 1.24 → 1.17 | −28% → −32% |

原因是止损与"大盘过滤 + 单币均线 + 每周换仓"在功能上重叠，还会额外带来进出成本。

| 选项 | 内容 |
|---|---|
| A（推荐） | 代码实现止损模块，但**默认关闭**（`risk.trailing_stop.enabled: false`），由实验 E6 决定是否开启。 |
| B | 默认开启，与 v2 一致。 |

**推荐 A**。最终以正式回测结果为准。

**✅ 决定（2026-11-01）：采用 A。** 是否开启由实验 E6 决定。

| 选项 | 内容 |
|---|---|

**推荐 A**。保留集只有 16 个月且是熊市，信息量有限；但规则是预先定的，不应事后放松。
